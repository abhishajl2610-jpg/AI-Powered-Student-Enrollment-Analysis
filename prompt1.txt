AI-POWERED STUDENT ENROLLMENT ANALYTICS
PHASE 2 — INTERACTIVE VISUALIZATION, DASHBOARD AND AI INSIGHTS

ROLE

Act as a Senior Data Analyst, BI Developer, Data Visualization Specialist and Analytics Application Developer.

Build a professional, interactive higher-education enrollment analytics dashboard based on the validated outputs created during Phase 1.

The dashboard should look and behave like a real-world analytics application rather than a simple collection of charts.

==================================================
1. IMPORTANT — USE PHASE 1 OUTPUTS
==================================================

Before building the dashboard:

1. Inspect the work completed in Phase 1.
2. Inspect the processed datasets.
3. Inspect the SQL/database outputs.
4. Inspect the trained Machine Learning model.
5. Inspect the prediction pipeline.
6. Inspect the Gemini integration.
7. Reuse validated outputs wherever possible.

Do NOT repeat the complete data-cleaning or ML workflow unnecessarily.

Do NOT create fake data for dashboard purposes.

Do NOT invent KPIs or insights.

==================================================
2. DASHBOARD OBJECTIVE
==================================================

Create an interactive dashboard for:

AI-Powered Student Enrollment Analytics

The dashboard should allow a user to understand:

- Overall enrollment
- Enrollment trends
- State/UT performance
- Program enrollment
- UG discipline enrollment
- PG/PhD discipline enrollment
- Gender patterns where available
- Growth patterns
- ML-based enrollment predictions
- AI-generated analytical explanations

==================================================
3. TECHNOLOGY
==================================================

Use Plotly for interactive visualizations.

Use an appropriate web application approach for the dashboard.

Preferred options:

- HTML
- CSS
- JavaScript
- Plotly.js

OR, if the project architecture benefits from it:

- Python-based dashboard framework
- FastAPI backend + frontend

Choose the simplest professional architecture that works reliably with the existing Phase 1 project.

Do not add unnecessary technologies.

==================================================
4. DASHBOARD STRUCTURE
==================================================

Create a clean professional dashboard with logical sections.

Recommended structure:

HEADER

AI-Powered Student Enrollment Analytics

Subtitle:

AISHE Higher Education Enrollment Analysis and Prediction

--------------------------------------------------

SECTION 1 — EXECUTIVE OVERVIEW

Display important KPI cards such as:

- Total Enrollment
- Latest Year Enrollment
- Enrollment Growth
- Number of States/UTs
- Number of Programs
- Number of Disciplines

Only display KPIs that are supported by the actual data.

Each KPI must be calculated from validated data.

--------------------------------------------------

SECTION 2 — ENROLLMENT TREND

Create an interactive time-series visualization showing:

- Year
- Total enrollment
- Enrollment growth where available

Allow the user to understand whether enrollment is increasing, decreasing or fluctuating.

Include useful hover information.

--------------------------------------------------

SECTION 3 — STATE / UT ANALYSIS

Create interactive visualizations for:

- Enrollment by State/UT
- Top States/UTs
- Bottom States/UTs where meaningful
- State/UT growth

Use suitable charts such as:

- Horizontal bar chart
- Map visualization if reliable geographic data is available
- Ranking chart

Do not use a map if the geographic mapping is unreliable.

--------------------------------------------------

SECTION 4 — PROGRAM ANALYSIS

Create visualizations showing:

- Enrollment by program
- Top programs
- Program contribution
- Program trends where data supports it

Use appropriate charts such as:

- Bar chart
- Treemap
- Line chart

Avoid unnecessary chart types.

--------------------------------------------------

SECTION 5 — UG DISCIPLINE ANALYSIS

Create interactive visualizations showing:

- UG discipline enrollment
- Top UG disciplines
- Gender distribution where available
- Discipline comparison

Allow useful filtering.

--------------------------------------------------

SECTION 6 — PG / PhD DISCIPLINE ANALYSIS

Create interactive visualizations showing:

- PG/PhD discipline enrollment
- Top disciplines
- Gender distribution where available
- Discipline comparison

Use suitable visualizations.

--------------------------------------------------

SECTION 7 — GENDER ANALYSIS

Where gender data is available, show:

- Male enrollment
- Female enrollment
- Gender share
- Gender gap
- Gender trends

Use clear and understandable visualizations.

Do not imply causation from gender differences.

9. GEMINI AI INSIGHTS
==================================================

Integrate Gemini as an AI-powered explanation layer.

The Gemini API key is stored securely in:

.env

using:

GEMINI_API_KEY

NEVER expose the actual API key.

NEVER hard-code it.

NEVER display it in the dashboard.

NEVER print it to logs.

10. AI INSIGHT FEATURES
==================================================

Create an:

"AI Insights"

or

"Ask AI"

section.

Possible functionality:

1. Generate AI Summary
2. Explain Current Dashboard
3. Explain Enrollment Trend
4. Explain State/UT Performance
5. Explain Program/Discipline Pattern
6. Explain ML Prediction

The AI should receive validated analytical results from the application.

For example, the application may provide:

- Current filters
- Total enrollment
- Growth percentage
- Top states
- Top programs
- Selected prediction
- Model information

Gemini then converts these validated values into natural-language explanations.

==================================================
11. GEMINI SAFETY AND ACCURACY
==================================================

IMPORTANT:

Gemini must NOT independently invent numerical values.

The application should calculate actual numbers using:

- Python
- SQL
- ML model

and then provide those results to Gemini.

Gemini's role is primarily:

- Explanation
- Summarization
- Natural-language interpretation

If Gemini cannot answer reliably, show an appropriate message instead of fabricating an answer.

==================================================
12. ASK-YOUR-DATA FEATURE
==================================================

If practical, create an:

"Ask Your Data"

input box.

Example questions:

"What is the enrollment trend?"

"Which State/UT has the highest enrollment?"

"Which program has the highest enrollment?"

"How has female enrollment changed?"

"What does the current ML prediction mean?"

The system should first retrieve or calculate the relevant validated data and then use Gemini to formulate a response.

Do NOT allow Gemini to directly invent database results.

==================================================
19. PERFORMANCE
==================================================

Avoid loading large raw datasets repeatedly for every chart interaction.

Prefer:

- Processed datasets
- SQL queries
- Cached analytical results
- Efficient filtering
- Reusable data-loading functions

Do not make unnecessary API calls to Gemini.

Call Gemini only when the user requests an AI explanation or when a clearly useful AI summary is required.

- KPIs
- Charts
